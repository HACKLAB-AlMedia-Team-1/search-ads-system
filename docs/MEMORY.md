- 2026-11-22 · SIMULATION RULES (user): "Simulate it" injects the fault into the running stream. It never ends by itself (`Runtime.inject` drops the scenario's `end`; only DQ1 keeps its one late hour, `ONE_OFF`) and it starts from a normal shop (`inject` calls `Simulator.restore`: ad budget back on plan). "End Simulation" (`Runtime.end_simulation`) only switches the fault off and repairs the store at once (search cache emptied, late delivery arrives, ad budget back on plan). It does NOT close the incident: the agent closes it after 3 normal hours that could be judged (`close_stale(hour, measured)`, `Pipeline._measured`; about 6 s at Normal speed in daytime, longer at night). Until then the step shows it as open with a note. `IncidentManager.fixed` marks it, so the same failure simulated again is a new incident with a fresh report, never a reopened one. `IncidentManager.resolve` is gone. Several simulations may overlap; `Runtime.active()` = started and not ended. Reason: the user wants to watch the agent see the recovery.
- 2026-11-22 · Own store actions count in the monitored numbers (user; replaces "panel only"): `Runtime.log_ux` -> `Simulator.shopper_action` / `_count_shopper` add each search, empty result, add-to-cart, blocked add-to-cart and order to the organic row of that country and device in the hour being simulated. One action = 100 shoppers, at most a tenth of that hour's shoppers on the same device, at least 1 (`SHOPPER_WEIGHT`, `SHOPPER_SHARE`, `SHOPPER_MIN`). Volume-neutral on purpose: the number of searches stays the same (a first version added shoppers and raised false "sessions far above expected" alerts); an empty search moves that crowd from "found products" to "found nothing", a search with results moves a crowd the other way, and clicks, carts and orders of successful searchers follow in proportion. Known cost: several empty searches in one simulated hour can raise an alert with no simulation running. The "Your store activity" strip (`Runtime.store_activity`, from `ux_events` by real time) still shows the person's own counts.
